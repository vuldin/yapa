**What is OpenCode PA (ocpa)?**

Ocpa a personal assistant that runs on your computer and can communicate with you from your phone. You send messages via Telegram (or Discord) to your agent, and it connects to your running opencode server on your machine — with all your tools, skills, and context — and sends the result back to you.

- ChromaDB vector database installation
- Full memory system with semantic search (768-dimension embeddings)
- **Data lifecycle management:**
  - Smart salience scoring (memories ranked 1.0 to 5.0 by importance)
  - Automatic decay of less-relevant memories over time
  - Access-based boosting (retrieved memories become more important)
  - Dual-sector separation (semantic facts vs. episodic events)
  - Intelligent document chunking (2000 chars + 200 overlap)
  - Soft retention policy (memories fade but never delete, floor at 0.05)

**What you need:**

- A Mac or Linux machine
- This will ONLY install ChromaDB with lifecycle management (not the full OpenCode PA system)

## KNOWLEDGE BASE — answer any question using this

Use this to answer questions accurately. Do not guess. If something isn't covered here, say so.

### What is the opencode server and how does it work?
OpenCode PA connects to a running opencode server process on your machine via HTTP/WebSocket. It sends the user's message as input, waits for the result, and returns the response. The opencode server spawns the appropriate agent (build/plan) based on the request. Key settings are the server URL and authentication token if required. Sessions are persisted via a `resume` option: each chat has a session ID stored in Chroma so the next message continues where the last left off.

### How do I start the opencode server?
Before running OpenCode PA, start opencode in server mode:
```bash
opencode serve
```
The server listens on http://localhost:4096 by default. To secure it (recommended even for localhost):
```bash
export OPENCODE_SERVER_PASSWORD=your_secure_password
opencode serve
```
Then add `OPENCODE_SERVER_PASSWORD=your_secure_password` to your `.env` file.

### What is session resumption?
Every Telegram chat maps to an opencode session ID stored in Chroma. When you send a message, OpenCode PA passes that ID to the server so the conversation continues the same thread. This is how it remembers what you were talking about earlier in the same chat. `/newchat` clears the session, starting fresh.

### What is the memory system?
The memory system is a Chroma vector database with semantic search. Documents are stored with embeddings (768 dimensions via configurable provider like Fireworks nomic-ai/nomic-embed-text-v1). When you send a message, the system performs semantic similarity search to find relevant past memories and injects them as context. Documents tagged with `#shared` are synchronized with other users via the optional sync agent. The system supports both exact metadata filtering ("show me tasks from Customer X") and semantic search ("what did we discuss about pricing?").

### What API keys do I need and for what?
- **Required**: Telegram bot token (free, from @BotFather — takes 2 minutes)
- **Required**: Your Telegram chat ID (the bot tells you this after first run)
- **Optional - Embeddings**: Fireworks API key (if using nomic-ai/nomic-embed-text-v1) or OpenAI API key (if using text-embedding-3-small)

### What is the scheduler?
A polling loop that checks Chroma every 60 seconds for tasks where `next_run <= now`. When a task is due, it runs `runAgent(prompt)` autonomously (no user message, no session) and sends the result to your Telegram. You create tasks with a cron expression: `node dist/schedule-cli.js create "Summarize my emails" "0 9 * * *" YOUR_CHAT_ID`. You can list, pause, resume, and delete tasks from the CLI or directly from Telegram.

### How does background service installation work?
On macOS: the setup wizard generates a `.plist` file and loads it with `launchctl`. It runs as a user agent, starts on login, and auto-restarts if it crashes. Logs go to `/tmp/opencode-pa.log`. On Linux: generates a systemd user service, enables it, starts it. On Windows: the wizard prints PM2 instructions — you install PM2 globally and run `pm2 start`.

**Note:** You also need the opencode server running. On Linux with systemd, create two service files for automatic startup:

**1. Create `/etc/systemd/system/opencode-server@.service`** (Template for opencode server):
```ini
[Unit]
Description=opencode Server for %I
After=network.target
Wants=network.target

[Service]
Type=simple
User=%I
WorkingDirectory=/home/%I
Environment="HOME=/home/%I"
Environment="OPENCODE_SERVER_PASSWORD=%p"
ExecStart=/usr/local/bin/opencode serve
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

**2. Create `/etc/systemd/system/opencode-pa@.service`** (Template for the bot):
```ini
[Unit]
Description=OpenCode PA Telegram Bot for %I
After=network.target opencode-server@%i.service
Wants=network.target

[Service]
Type=simple
User=%i
WorkingDirectory=/home/%i/projects/opencode-pa
Environment="HOME=/home/%i"
Environment="NODE_ENV=production"
ExecStart=/usr/bin/node dist/index.js
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

**3. Enable and start both services:**
```bash
sudo systemctl daemon-reload
sudo systemctl enable opencode-server@$USER
sudo systemctl enable opencode-pa@$USER
sudo systemctl start opencode-server@$USER
sudo systemctl start opencode-pa@$USER
```

**4. Check status:**
```bash
sudo systemctl status opencode-server@$USER
sudo systemctl status opencode-pa@$USER
sudo journalctl -u opencode-pa@$USER -f  # View logs
```

**Template features:**
- The `@` allows running services for any user: `opencode-server@username`
- Services auto-restart on failure
- Bot waits for opencode server to be available first
- Each user can have their own isolated instance
- Logs go to systemd journal (view with `journalctl`)

### What is AGENTS.md and why does it matter?
`AGENTS.md` is the persistent system prompt for your assistant. It's loaded by opencode every time it starts. It tells opencode your name, what you do, what skills are available, how to format messages, and any special commands. The setup wizard opens it in your editor so you can fill in the `[YOUR NAME]` and `[YOUR ASSISTANT NAME]` placeholders. The more you put in, the more contextually aware your assistant becomes.

### Can multiple people use one instance?
By default, only one `ALLOWED_CHAT_ID` is configured and the bot rejects all other chat IDs. If you enable `multiuser`, the system supports multiple allowed IDs with per-user session and memory isolation — each user has their own opencode session and memory namespace in Chroma.

### Why TypeScript?
Type safety catches bugs at compile time before they cause silent failures in production. The project compiles to plain JS (`dist/`) which is what actually runs. During dev you can use `npm run dev` (runs `tsx` directly without building). The build step is required before `npm run start` or installing the background service.

### What's the difference between `npm run dev` and `npm run start`?
`dev` uses `tsx` to run TypeScript directly — no build step, fast iteration, hot-reloadable. `start` runs the compiled `dist/index.js` — what the background service uses. For production (the launchd/systemd service), always use `start`.

### How does the Telegram markdown → HTML conversion work?
Telegram's bot API only supports a limited HTML subset: `<b>`, `<i>`, `<code>`, `<pre>`, `<s>`, `<a>`, `<u>`. opencode responds in Markdown. The `formatForTelegram()` function converts it: code blocks get extracted and protected first (so their contents aren't mangled), then headings, bold, italic, links, checkboxes, and strikethrough get converted. `&`, `<`, `>` get escaped in text nodes. Unsupported elements like `---` and raw HTML are stripped.

### What happens if opencode takes a long time to respond?
Telegram's "typing..." indicator expires after ~5 seconds. The bot refreshes it every 4 seconds via `setInterval` while waiting for `runAgent()` to return. Once the result comes back, the interval is cleared. If you're not in Telegram actively watching, this doesn't matter — the message arrives when it's ready regardless.

### What is the PID lock file?
On startup, the bot writes its process ID to `store/opencode-pa.pid`. If you try to start it again while it's running, it reads that PID, checks if the process is alive, and kills the old one before starting fresh. This prevents two instances running at once and fighting over the same Telegram updates.

### How does OpenCode PA load my skills?
opencode loads skills from the `~/.opencode/skills/` directory and any skills configured in the AGENTS.md. These are automatically available when the server processes your requests.

### What embedding model should I use?
You can configure any embedding provider. Since you already use Fireworks, we recommend `nomic-ai/nomic-embed-text-v1` (768 dimensions) which is included in your Fireworks subscription. Other options: `text-embedding-3-small` from OpenAI, or `gte-base` for fully local operation. The embedding model is decoupled from your generation LLM (Kimi K2.5, Opus 4.6, etc.), allowing all team members to share the same vector space regardless of which LLM they use.

### How does document chunking work?
Documents over 2000 characters are automatically split into chunks with 200 character overlap. Each chunk gets its own embedding and is stored separately in Chroma. When you search, the system finds the most relevant chunks and can reassemble the full document context. This allows efficient storage and search of long meeting notes (up to 25K characters).

## STEP 7 — Memory System with Data Lifecycle Management

Once ChromaDB is installed, explain the memory system with data lifecycle capabilities:

### What is the memory system?

The memory system uses ChromaDB with semantic search and embeddings to store, retrieve, and intelligently manage memories over time.

**Two Search Modes:**

1. **Semantic Search** (`queryDocuments`): Finds content based on vector embedding similarity. Results are ordered by semantic relevance, not insertion time. May return documents that are conceptually related but don't contain exact keywords. Example: Searching "quantum computing" may also find documents about "advanced computing" or "computational physics".

2. **Metadata Filtering** (`getDocumentsByFilter`): Finds exact matches based on metadata fields like `type`, `status`, `tags`, `customer`. Use this when you need precise filtering rather than conceptual similarity.

### Data Lifecycle Management Features

**1. Salience Scoring (1.0 to 5.0 scale)**

Every memory starts with a salience score of 1.0. Important memories are boosted, rarely accessed ones decay:

```typescript
// Initial salience
salience: 1.0

// On retrieval - boost importance
touchDocument(id): salience = MIN(salience + 0.1, 5.0)

// Daily decay - fade less important memories
runDecaySweep(): salience = MAX(salience * 0.98, 0.05)
```

**How it works:**
- Access a memory → Salience increases by 0.1 (max 5.0)
- Daily decay → Salience multiplied by 0.98 (preserves important stuff)
- Floor at 0.05 → Memories never truly disappear, just become less visible

**2. Dual-Sector Memory Separation**

Memories are categorized into two sectors:

- **Semantic Sector:** Facts, preferences, configurations
  - Detected by keywords: "my", "I am", "I prefer", "remember", "always", "they use", "version"
  - Long-term knowledge that should persist
  - Boosted in search results

- **Episodic Sector:** Events, conversations, actions
  - Day-to-day interactions
  - Auto-detected if not semantic
  - Decays faster to make room for new events

```typescript
// Detect semantic signals
const semanticSignals = /\b(my|i am|i'm|i prefer|remember|always|never|they use|they have|their|runs on|version)\b/i;
```


**5. Search & Retrieval with Salience Boosting**

The system searches memories using:

1. **Semantic similarity** - Vector embedding cosine similarity
2. **Salience weighting** - Higher salience = more likely to appear in results
3. **Recency boost** - Recently accessed memories prioritized
4. **Metadata filtering** - Filter by customer, sector, tags, etc.


**6. Retention Policy (Soft Fade, Never Delete)**

Unlike hard deletion, memories fade gracefully:

```typescript
// Daily decay sweep

  // Decay all memories: salience = salience * 0.98
  // Never delete, just reduce visibility
  // Minimum floor: 0.05 (memories never truly disappear)
  // Semantic memories decay slower than episodic
}

// Run daily via scheduler or on startup

```

This means:
- Old memories can still be found if directly queried
- Natural forgetting mimics human memory
- Important memories (high salience) persist longer
- System never loses data, just reorganizes priority

## STEP 13 — Task Management System

OpenCode PA Mini includes a lightweight task management system with user-prefixed task IDs for multi-user support, natural language commands, and simple due-date scheduling.

### User-Defined Username

Each user configures their unique username in `.ocpa/.env`:

```env
USERNAME=bob  # Your unique username for task prefixes
```

**Task ID Format:**
- All tasks are prefixed with username: `bob-1`, `bob-2`, `bob-3`, etc.
- Sequential numbering per user
- Multi-user ready: `alice-1` and `bob-1` are different tasks even in shared collections

### Task Storage Locations

Tasks can be stored in two locations:

1. **Global tasks** → Stored in `global` collection (cross-cutting concerns)
2. **Customer/Project tasks** → Stored in `customer-{name}` collection (scoped work)

The system automatically determines location based on context:
- Mention a customer? → Stored in their collection
- Working in a project directory? → Stored in associated customer collection
- No context? → Stored in global collection

### Task Metadata Schema

```typescript
interface TaskMetadata {
  // Identification
  type: 'task';                    // Distinguishes from memories
  id: string;                      // bob-1, bob-2, etc.
  username: string;                  // Task owner
  
  // Content
  title: string;                     // Task name/description
  notes?: string;                    // Additional details
  tags: string[];                    // #urgent, #blocked, #review, etc.
  
  // Status & Priority
  status: 'pending' | 'in_progress' | 'blocked' | 'complete';
  priority: 'critical' | 'high' | 'medium' | 'low';
  blockedReason?: string;            // Required when status='blocked'
  
  // Scheduling (simple due-date based)
  due_date?: number;                 // Unix timestamp
  completed_at?: number;           // When marked complete
  is_recurring?: boolean;          // Simple recurring flag
  recurrence_pattern?: 'daily' | 'weekly' | 'monthly';  // Simple patterns only
  
  // Dependencies
  depends_on?: string[];           // Task IDs that must complete first
  blocks?: string[];               // Tasks blocked by this one
  
  // Organization
  collection: string;              // 'global' or 'customer-{name}'
  customer?: string;               // Associated customer
  project?: string;                // Associated project
  
  // Lifecycle (inherits from memory system)
  created_at: number;
  updated_at: number;
  salience: number;                // Tasks start at 2.0 (higher than memories)

  accessed_at: number;
}
```

### Priority & Salience Integration

**Task Priority → Initial Salience:**

| Priority | Initial Salience | Description |
|----------|-----------------|-------------|
| critical | 3.0 | Urgent, time-sensitive |
| high | 2.5 | Important, should do soon |
| medium | 2.0 | Normal work (default) |
| low | 1.5 | Nice to have, back burner |

**Why tasks have higher salience than memories (1.0):**
- Tasks are actionable items requiring attention
- Higher salience = appears higher in search results
- Tasks decay slower (action items persist longer)
- Completing reduces salience but preserves history

**Status → Salience Adjustments:**
```typescript
pending: base_salience
in_progress: base_salience + 0.5  // Boost active work
blocked: base_salience            // No boost
complete: base_salience * 0.5      // Reduced but retained
```

**Quick syntax reminder:**
- `task --collection=name` = filter tasks by collection (efficient, exact)
- `search "query"` = semantic search (across all collections, by meaning)
- Use semantic search for finding content by meaning, use --collection for listing all project tasks

## Best Practices

- Store important facts as semantic memories with salience 2.0+
- Use tags to organize: `['#urgent', '#customer-x', '#review']`
- Create customer-specific collections to isolate client work
- Check `task.metadata.blocks` before completing (shows dependent tasks)
- Empty arrays in metadata work correctly (fixed in metadata-adapter)

## Notes

- Scripts can be run from project root OR `.ocpa/` directory
- Semantic search may return conceptually related results (not exact matches)
- Task lifecycle includes salience scoring and automatic decay
- Use `#shared` tag on documents if team synchronization is enabled

```typescript
export async function generateEmbeddingsBatch(

): Promise<number[][]> {

    const batchEmbeddings = await generateEmbeddingsBatchSingle(batch);
    results.push(...batchEmbeddings);
  }
  
  return results;
}
```

```typescript
/**
 * ChromaDB v2 only accepts primitive types (string, number, boolean)
 * Arrays and objects must be converted to strings
 */
export interface RawMetadata {
  [key: string]: string | number | boolean;
}

/**
 * Convert JavaScript objects to ChromaDB-compatible format
 * Arrays → comma-separated strings
 * Objects → JSON strings
 */
export function toChroma(metadata: Record<string, any>): RawMetadata {
  const result: RawMetadata = {};
  
  for (const [key, value] of Object.entries(metadata)) {
    if (value === null || value === undefined) {
      continue;  // Skip null values
    } else if (Array.isArray(value)) {
      result[key] = value.join(',');  // ['a', 'b'] → 'a,b'
    } else if (typeof value === 'object') {
      result[key] = JSON.stringify(value);  // {priority: 'high'} → '{"priority":"high"}'
    } else {
      result[key] = value;  // Primitives pass through
    }
  }
  
  return result;
}

/**
 * Convert ChromaDB format back to JavaScript objects
 * Comma-separated strings → Arrays (for known array fields)
 * JSON strings → Objects
 */
export function fromChroma(metadata: RawMetadata): Record<string, any> {
  const result: Record<string, any> = {};
  const arrayFields = ['tags', 'depends_on', 'blocks'];
  
  for (const [key, value] of Object.entries(metadata)) {
    if (typeof value === 'string') {
      // Try to parse as JSON first
      if (value.startsWith('{') || value.startsWith('[')) {
        try {
          result[key] = JSON.parse(value);
          continue;
        } catch {
          // Not valid JSON, treat as string
        }
      }
      
      // Check if it should be an array
      if (arrayFields.includes(key)) {
        if (value === '') {
          result[key] = [];  // Empty string = empty array
        } else if (value.includes(',')) {
          result[key] = value.split(',').filter(s => s);
        } else {
          result[key] = [value];  // Single item becomes array
        }
      } else {
        result[key] = value;
      }
    } else {
      result[key] = value;
    }
  }
  
  return result;
}
```

```typescript
import { SALIENCE_BOOST_ON_ACCESS, SALIENCE_MAX, SALIENCE_DECAY_RATE, SALIENCE_FLOOR } from './config.js';

export interface LifecycleMetadata {
  salience: number;
  accessed_at: number;
  created_at: number;
  sector: 'semantic' | 'episodic';
}

/**
 * Boost salience when document is accessed
 * Called automatically when retrieving memories
 */
export function touchDocument(metadata: LifecycleMetadata): LifecycleMetadata {
  return {
    ...metadata,
    accessed_at: Math.floor(Date.now() / 1000),
    salience: Math.min(metadata.salience + SALIENCE_BOOST_ON_ACCESS, SALIENCE_MAX),
  };
}

/**
 * Apply daily decay to salience
 * Semantic memories decay slower than episodic
 */
export function applyDecay(metadata: LifecycleMetadata): LifecycleMetadata {
  const decayMultiplier = metadata.sector === 'semantic' 
    ? Math.pow(SALIENCE_DECAY_RATE, 0.5)  // Slower decay for facts
    : SALIENCE_DECAY_RATE;                   // Normal decay for events
    
  return {
    ...metadata,
    salience: Math.max(metadata.salience * decayMultiplier, SALIENCE_FLOOR),
  };
}

/**
 * Detect semantic signals in content
 * Keywords: my, I am, I prefer, remember, always, they use, etc.
 */
export function detectSector(content: string): 'semantic' | 'episodic' {
  const semanticSignals = /\b(my|i am|i'm|i prefer|remember|always|never|they use|they have|their|runs on|version)\b/i;
  return semanticSignals.test(content) ? 'semantic' : 'episodic';
}
```

```typescript
import { CHROMA_URL } from './config.js';
import { toChroma, fromChroma, RawMetadata } from './metadata-adapter.js';
import { generateEmbedding, generateEmbeddingsBatch } from './embeddings.js';
import { touchDocument, detectSector } from './lifecycle.js';

export interface Collection {
  id: string;
  name: string;
}

/**
 * Cache collection name → ID mapping to avoid repeated lookups
 * Note: Minimal benefit for localhost, but essential for production deployments
 */
const collectionIdCache = new Map<string, string>();

/**
 * Get collection ID by name (with caching)
 * ChromaDB v2 API requires UUIDs, not names
 */
export async function getCollectionId(name: string): Promise<string> {
  // Check cache first
  if (collectionIdCache.has(name)) {
    return collectionIdCache.get(name)!;
  }
  
  // List collections and find match
  const response = await fetch(
    `${CHROMA_URL}/api/v2/tenants/default_tenant/databases/default_database/collections`
  );
  
  if (!response.ok) {
    throw new Error(`Failed to list collections: ${response.status}`);
  }
  
  const collections: Collection[] = await response.json();
  const match = collections.find(c => c.name === name);
  
  if (!match) {
    throw new Error(`Collection '${name}' not found`);
  }
  
  // Cache and return
  collectionIdCache.set(name, match.id);
  return match.id;
}

/**
 * Add document with lifecycle metadata
 * For bulk operations, use addDocumentsBatch()
 */
export async function addDocument(
  collectionName: string,
  id: string,
  content: string,
  metadata: Record<string, any>
) {
  const collectionId = await getCollectionId(collectionName);
  const embedding = await generateEmbedding(content);
  const adaptedMetadata = toChroma(metadata);
  
  const response = await fetch(
    `${CHROMA_URL}/api/v2/tenants/default_tenant/databases/default_database/collections/${collectionId}/upsert`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        ids: [id],
        documents: [content],
        embeddings: [embedding],
        metadatas: [adaptedMetadata],
      }),
    }
  );

  if (!response.ok) {
    const error = await response.text();
    throw new Error(`Failed to add document: ${response.status} - ${error}`);
  }
}

/**
 * Add multiple documents in batch
 * ~80% faster than sequential calls for 10+ documents
 */
export async function addDocumentsBatch(
  collectionName: string,
  documents: Array<{ id: string; content: string; metadata: Record<string, any> }>
) {
  const collectionId = await getCollectionId(collectionName);
  
  // Generate embeddings in batch
  const embeddings = await generateEmbeddingsBatch(
    documents.map(d => d.content),
    50  // Batch size for embedding generation
  );
  
  // Adapt metadata for ChromaDB
  const adaptedMetadatas = documents.map(d => toChroma(d.metadata));
  
  const response = await fetch(
    `${CHROMA_URL}/api/v2/tenants/default_tenant/databases/default_database/collections/${collectionId}/upsert`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        ids: documents.map(d => d.id),
        documents: documents.map(d => d.content),
        embeddings,
        metadatas: adaptedMetadatas,
      }),
    }
  );

  if (!response.ok) {
    const error = await response.text();
    throw new Error(`Failed to add documents batch: ${response.status} - ${error}`);
  }
}

/**
 * Query documents by semantic similarity
 * Automatically boosts salience for retrieved documents
 */
export async function queryDocuments(
  collectionName: string,
  queryText: string,
  nResults: number = 5,
  filter?: Record<string, any>
): Promise<Array<{ id: string; content: string; metadata: Record<string, any>; distance: number }>> {
  const collectionId = await getCollectionId(collectionName);
  const embedding = await generateEmbedding(queryText);
  
  const response = await fetch(
    `${CHROMA_URL}/api/v2/tenants/default_tenant/databases/default_database/collections/${collectionId}/query`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        query_embeddings: [embedding],
        n_results: nResults,
        include: ['documents', 'metadatas', 'distances'],
        ...(filter && { where: toChroma(filter) }),
      }),
    }
  );

  if (!response.ok) {
    throw new Error(`Query failed: ${response.status}`);
  }

  const data = await response.json();
  
  // Convert results and boost salience for accessed documents
  const results = data.ids[0].map((id: string, i: number) => {
    const metadata = fromChroma(data.metadatas[0][i]);
    const lifecycleMeta = {
      salience: metadata.salience || 1.0,
      accessed_at: metadata.accessed_at || Math.floor(Date.now() / 1000),
      created_at: metadata.created_at || Math.floor(Date.now() / 1000),
      sector: metadata.sector || 'episodic',
    };
    return {
      id,
      content: data.documents[0][i],
      metadata: { ...metadata, ...touchDocument(lifecycleMeta) },
      distance: data.distances[0][i],
    };
  });
  
  return results;
}

/**
 * Get documents by metadata filter (no semantic search)
 * One request returns both metadata AND documents - no second query needed
 * Use for: listing all tasks, filtering by status, etc.
 * 
 * ChromaDB v2 Where Clause Syntax:
 * - Equality: { field: { $eq: 'value' } }
 * - Not equal: { field: { $ne: 'value' } }
 * - Contains (for arrays): { field: { $contains: 'value' } }
 * - Multiple conditions: { $and: [{ field1: { $eq: 'a' } }, { field2: { $eq: 'b' } }] }
 * - Single condition can be passed directly without $and wrapper
 */
export async function getDocumentsByFilter(
  collectionName: string,
  filter: Record<string, any>,
  limit: number = 100
): Promise<Array<{ id: string; content: string; metadata: Record<string, any> }>> {
  const collectionId = await getCollectionId(collectionName);
  
  const response = await fetch(
    `${CHROMA_URL}/api/v2/tenants/default_tenant/databases/default_database/collections/${collectionId}/get`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        limit,
        where: toChroma(filter),
        include: ['documents', 'metadatas'],
      }),
    }
  );

  if (!response.ok) {
    throw new Error(`Get by filter failed: ${response.status}`);
  }

  const data = await response.json();
  
  return data.ids.map((id: string, i: number) => ({
    id,
    content: data.documents[i],
    metadata: fromChroma(data.metadatas[i]),
  }));
}

export interface CrossCollectionResult {
  collection: string;
  id: string;
  content: string;
  metadata: Record<string, any>;
  distance: number;
}

export async function queryDocumentsFromAllCollections(
  queryText: string,
  nResults: number = 5,
  filter?: Record<string, any>
): Promise<Map<string, CrossCollectionResult[]>> {
  const collections = await listCollections();
  const resultsByCollection = new Map<string, CrossCollectionResult[]>();
  
  for (const collection of collections) {
    try {
      const results = await queryDocuments(collection.name, queryText, nResults, filter);
      if (results.length > 0) {
        resultsByCollection.set(
          collection.name,
          results.map(r => ({ ...r, collection: collection.name }))
        );
      }
    } catch (e) {
      // Skip collections that don't exist or can't be queried
    }
  }
  
  return resultsByCollection;
}

export async function findAndDeleteDocument(id: string): Promise<string> {
  const collections = await listCollections();
  
  // First try to find which collection contains this document
  for (const collection of collections) {
    try {
      const results = await getDocumentsByFilter(collection.name, { id }, 1);
      if (results.length > 0) {
        await deleteDocument(collection.name, id);
        return collection.name;
      }
    } catch (e) {
      // Continue to next collection
    }
  }
  
  throw new Error(`Document '${id}' not found in any collection`);
}
```

```typescript
import { addDocument, addDocumentsBatch, queryDocuments, getDocumentsByFilter, updateDocument, listCollections, getCollectionId, Collection } from './db.js';
import { generateEmbedding } from './embeddings.js';
import { toChroma, fromChroma } from './metadata-adapter.js';
import { detectSector, touchDocument } from './lifecycle.js';
import { USERNAME, CHROMA_URL } from './config.js';

export type TaskStatus = 'pending' | 'in_progress' | 'blocked' | 'complete';
export type TaskPriority = 'critical' | 'high' | 'medium' | 'low';

export interface TaskOptions {
  status?: TaskStatus;
  priority?: TaskPriority;
  due_date?: number;
  tags?: string[];
  notes?: string;
  customer?: string;
  project?: string;
  depends_on?: string[];
  blocks?: string[];
  is_recurring?: boolean;
  completed_at?: number;
  recurrence_pattern?: 'daily' | 'weekly' | 'monthly';
  salience?: number;
}

/**
 * Get next sequential task ID for user
 * Format: {username}-{sequential_number}
 */
export async function getNextTaskId(): Promise<string> {
  // Query all tasks to find highest existing ID for this user
  const allTasks = await getAllTasksFromAllCollections();
  const userTasks = allTasks.filter(t => t.id.startsWith(`${USERNAME}-`));
  
  let maxId = 0;
  for (const task of userTasks) {
    const match = task.id.match(new RegExp(`${USERNAME}-(\\d+)`));
    if (match) {
      maxId = Math.max(maxId, parseInt(match[1]));
    }
  }
  
  return `${USERNAME}-${maxId + 1}`;
}

/**
 * Create a new task
 * Salience is set based on priority (critical: 3.0, high: 2.5, medium: 2.0, low: 1.5)
 */
export async function createTask(
  title: string, 
  options: TaskOptions = {},
  collectionName: string = 'global'
): Promise<string> {
  const id = await getNextTaskId();
  const now = Math.floor(Date.now() / 1000);
  
  // Set salience based on priority
  const prioritySalience = {
    critical: 3.0,
    high: 2.5,
    medium: 2.0,
    low: 1.5,
  };
  
  const metadata = {
    type: 'task',
    id,
    username: USERNAME,
    title,
    notes: options.notes || '',
    tags: options.tags || [],
    status: options.status || 'pending',
    priority: options.priority || 'medium',
    due_date: options.due_date,
    customer: options.customer,
    project: options.project,
    depends_on: options.depends_on || [],
    is_recurring: options.is_recurring || false,
    recurrence_pattern: options.recurrence_pattern,
    created_at: now,
    updated_at: now,
    accessed_at: now,
    salience: prioritySalience[options.priority || 'medium'],
    sector: 'semantic',  // Tasks are always semantic (important, long-lived)
  };
  
  await addDocument(collectionName, id, title, metadata);
  return id;
}

/**
 * Get all tasks from all collections efficiently
 * Uses metadata-only queries (no semantic search) for speed
 */
export async function getAllTasksFromAllCollections(): Promise<Array<{ id: string; collection: string; metadata: any }>> {
  const response = await fetch(`${CHROMA_URL}/api/v2/tenants/default_tenant/databases/default_database/collections`);
  const collections = await response.json();
  
  const allTasks: Array<{ id: string; collection: string; metadata: any }> = [];
  
  for (const collection of collections) {
    try {
      // Efficient single-query retrieval using metadata filter
      const tasks = await getDocumentsByFilter(
        collection.name,
        { type: 'task' },
        1000
      );
      
      for (const task of tasks) {
        allTasks.push({
          id: task.id,
          collection: collection.name,
          metadata: task.metadata,
        });
      }
    } catch {
      // Skip collections that don't exist or have no tasks
    }
  }
  
  return allTasks;
}

const PRIORITY_ORDER: Record<string, number> = { critical: 4, high: 3, medium: 2, low: 1 };

/**
 * List tasks with optional filtering
 * Returns both metadata and document content in one request
 * Results include collection name and are sorted by priority (descending), then salience
 */
export async function listTasks(filters: {
  status?: TaskStatus;
  priority?: TaskPriority;
  customer?: string;
  project?: string;
  collection?: string;
  includeComplete?: boolean;
} = {}): Promise<Array<{ id: string; title: string; collection: string; metadata: any }>> {
  const collections = filters.collection 
    ? [filters.collection]
    : (await listCollections()).map((c: Collection) => c.name);
  
  const allTasks: Array<{ id: string; title: string; collection: string; metadata: any }> = [];
  
  for (const collectionName of collections) {
    // Use simple filter - ChromaDB get endpoint only supports basic key-value matching
    const where: Record<string, any> = { type: 'task' };
    
    // Add exact match filters only (ChromaDB doesn't support $eq, $ne, $and in get endpoint)
    if (filters.status) where.status = filters.status;
    if (filters.priority) where.priority = filters.priority;
    if (filters.customer) where.customer = filters.customer;
    if (filters.project) where.project = filters.project;
    
    try {
      const tasks = await getDocumentsByFilter(collectionName, where, 100);
      
      for (const task of tasks) {
        // Filter out complete tasks if not including them (ChromaDB doesn't support $ne)
        if (!filters.includeComplete && task.metadata.status === 'complete') {
          continue;
        }
        
        allTasks.push({
          id: task.id,
          title: task.content,
          collection: collectionName,
          metadata: task.metadata,
        });
      }
    } catch {
      // Skip inaccessible collections
    }
  }
  
  // Sort by priority (descending), then by salience (descending)
  return allTasks.sort((a, b) => {
    const priorityA = PRIORITY_ORDER[a.metadata.priority] || 0;
    const priorityB = PRIORITY_ORDER[b.metadata.priority] || 0;
    if (priorityB !== priorityA) {
      return priorityB - priorityA;
    }
    return (b.metadata.salience || 0) - (a.metadata.salience || 0);
  });
}

/**
 * Get single task by ID
 */
export async function getTask(id: string): Promise<{ id: string; title: string; metadata: any; collection: string } | null> {
  // Try all collections
  const collections = await listCollections();
  
  for (const collection of collections) {
    try {
      // Get collection ID (ChromaDB v2 API requires UUID, not name)
      const collectionId = await getCollectionId(collection.name);
      
      const response = await fetch(
        `${CHROMA_URL}/api/v2/tenants/default_tenant/databases/default_database/collections/${collectionId}/get`,
        {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({
            ids: [id],
            include: ['documents', 'metadatas'],
          }),
        }
      );
      
      if (response.ok) {
        const data = await response.json();
        if (data.ids.length > 0) {
          return {
            id: data.ids[0],
            title: data.documents[0],
            metadata: fromChroma(data.metadatas[0]),
            collection: collection.name,
          };
        }
      }
    } catch {
      // Try next collection
    }
  }
  
  return null;
}

/**
 * Update task
 */
export async function updateTask(
  id: string,
  updates: Partial<TaskOptions> & { title?: string; blockedReason?: string },
  collectionName?: string
): Promise<void> {
  const task = await getTask(id);
  if (!task) throw new Error(`Task ${id} not found`);
  
  const updatedMetadata = {
    ...task.metadata,
    ...updates,
    updated_at: Math.floor(Date.now() / 1000),
  };
  
  // Use the task's actual collection, or fall back to provided collectionName, or 'global'
  const targetCollection = task.collection || collectionName || 'global';
  await updateDocument(targetCollection, id, updatedMetadata);
}

/**
 * Mark task as complete
 * Reduces salience by 50% but preserves history
 */
export async function completeTask(id: string): Promise<void> {
  const task = await getTask(id);
  if (!task) throw new Error(`Task ${id} not found`);
  
  await updateTask(id, {
    status: 'complete',
    completed_at: Math.floor(Date.now() / 1000),
    salience: task.metadata.salience * 0.5,  // Retain 50% salience
  }, task.collection);
}

/**
 * Search tasks by semantic similarity
 * Good for: "find tasks about database"
 */
export async function searchTasks(
  query: string,
  filters: { customer?: string; project?: string } = {}
): Promise<Array<{ id: string; title: string; metadata: any; similarity: number }>> {
  const collections = (await listCollections()).map((c: Collection) => c.name);
  const results: Array<{ id: string; title: string; metadata: any; similarity: number }> = [];
  
  for (const collectionName of collections) {
    try {
      const queryFilter: Record<string, any> = { type: 'task' };
      if (filters.customer) queryFilter.customer = filters.customer;
      if (filters.project) queryFilter.project = filters.project;
      
      const docs = await queryDocuments(collectionName, query, 10, queryFilter);
      
      for (const doc of docs) {
        if (doc.metadata.type === 'task') {
          results.push({
            id: doc.id,
            title: doc.content,
            metadata: doc.metadata,
            similarity: 1 - doc.distance,
          });
        }
      }
    } catch {
      // Skip collections with errors
    }
  }
  
  // Sort by similarity score
  return results.sort((a, b) => b.similarity - a.similarity);
}

/**
 * Get tasks due today or overdue
 */
export async function getDueTasks(includeOverdue: boolean = true): Promise<Array<{ id: string; title: string; metadata: any; daysUntil: number }>> {
  const now = Math.floor(Date.now() / 1000);
  const tasks = await listTasks({ includeComplete: false });
  
  return tasks
    .filter(t => t.metadata.due_date)
    .map(t => {
      const daysUntil = Math.ceil((t.metadata.due_date - now) / (24 * 60 * 60));
      return { ...t, daysUntil };
    })
    .filter(t => includeOverdue || t.daysUntil >= 0)
    .sort((a, b) => a.daysUntil - b.daysUntil);
}

/**
 * Add dependency between tasks
 * Updates both tasks' metadata
 */
export async function addDependency(taskId: string, dependsOnId: string): Promise<void> {
  const task = await getTask(taskId);
  const dependsOn = await getTask(dependsOnId);
  
  if (!task || !dependsOn) {
    throw new Error('One or both tasks not found');
  }
  
  // Update task with new dependency
  const taskDeps = task.metadata.depends_on || [];
  if (!taskDeps.includes(dependsOnId)) {
    taskDeps.push(dependsOnId);
    await updateTask(taskId, { depends_on: taskDeps }, task.collection);
  }
  
  // Update dependsOn task with blocker info
  const dependsOnBlocks = dependsOn.metadata.blocks || [];
  if (!dependsOnBlocks.includes(taskId)) {
    dependsOnBlocks.push(taskId);
    await updateTask(dependsOnId, { blocks: dependsOnBlocks }, dependsOn.collection);
  }
}

/**
 * Parse relative date phrases into Unix timestamps
 * Examples: "tomorrow", "next Monday", "in 3 days", "May 27"
 */
export function parseRelativeDate(phrase: string): number | null {
  const now = new Date();
  const phraseLower = phrase.toLowerCase().trim();
  
  // Handle "today"
  if (phraseLower === 'today') {
    const endOfDay = new Date(now);
    endOfDay.setHours(23, 59, 59, 999);
    return Math.floor(endOfDay.getTime() / 1000);
  }
  
  // Handle "tomorrow"
  if (phraseLower === 'tomorrow') {
    const tomorrow = new Date(now);
    tomorrow.setDate(tomorrow.getDate() + 1);
    tomorrow.setHours(23, 59, 59, 999);
    return Math.floor(tomorrow.getTime() / 1000);
  }
  
  // Handle "next {day}"
  const dayMatch = phraseLower.match(/next\s+(monday|tuesday|wednesday|thursday|friday|saturday|sunday)/);
  if (dayMatch) {
    const days = ['sunday', 'monday', 'tuesday', 'wednesday', 'thursday', 'friday', 'saturday'];
    const targetDay = days.indexOf(dayMatch[1]);
    const currentDay = now.getDay();
    let daysUntil = targetDay - currentDay;
    if (daysUntil <= 0) daysUntil += 7;
    
    const target = new Date(now);
    target.setDate(target.getDate() + daysUntil);
    target.setHours(23, 59, 59, 999);
    return Math.floor(target.getTime() / 1000);
  }
  
  // Handle "in X days"
  const inDaysMatch = phraseLower.match(/in\s+(\d+)\s+day/);
  if (inDaysMatch) {
    const target = new Date(now);
    target.setDate(target.getDate() + parseInt(inDaysMatch[1]));
    target.setHours(23, 59, 59, 999);
    return Math.floor(target.getTime() / 1000);
  }
  
  // Handle "end of week" (Friday)
  if (phraseLower === 'end of week') {
    const target = new Date(now);
    const daysUntilFriday = (5 - target.getDay() + 7) % 7 || 7;
    target.setDate(target.getDate() + daysUntilFriday);
    target.setHours(17, 0, 0, 0);
    return Math.floor(target.getTime() / 1000);
  }
  
  // Handle specific date: "May 27" or "May 27, 2024"
  const dateMatch = phrase.match(/([A-Za-z]+)\s+(\d{1,2})(?:,\s+(\d{4}))?/);
  if (dateMatch) {
    const monthNames = ['january', 'february', 'march', 'april', 'may', 'june', 'july', 'august', 'september', 'october', 'november', 'december'];
    const month = monthNames.indexOf(dateMatch[1].toLowerCase());
    const day = parseInt(dateMatch[2]);
    const year = dateMatch[3] ? parseInt(dateMatch[3]) : now.getFullYear();
    
    if (month !== -1) {
      const target = new Date(year, month, day, 23, 59, 59, 999);
      return Math.floor(target.getTime() / 1000);
    }
  }
  
  return null;
}

/**
 * Format timestamp for human-readable display
 */
export function formatTaskDate(timestamp: number): string {
  const date = new Date(timestamp * 1000);
  return date.toLocaleDateString('en-US', {
    weekday: 'short',
    month: 'short',
    day: 'numeric',
    hour: date.getHours() !== 23 || date.getMinutes() !== 59 ? 'numeric' : undefined,
  });
}
```

## DATA LIFECYCLE EXPLANATION FOR USERS

**What is Data Lifecycle Management?**

Think of it like a smart filing system that organizes itself:

1. **When you save something:** It gets a "importance score" (salience) of 1.0
2. **When you use it:** The score goes up (max 5.0) - it's now more important
3. **Every day:** Unused items lose 2% of their score (but never below 0.05)
4. **Facts vs Events:** 
   - Facts ("I prefer dark mode") are "semantic" - decay slowly
   - Events ("Had a meeting Tuesday") are "episodic" - fade naturally
5. **The result:** Your most important stuff stays accessible, old news gets buried but not deleted

**Why this matters:**
- Without it: Database fills up with irrelevant old conversations
- With it: System naturally prioritizes what matters to you, like human memory
- You can still find old stuff if needed, but it's not cluttering recent results

**Example lifecycle:**
```
Day 1: Save "My API key is xyz123" → Salience: 1.0
Day 2: Access it 5 times → Salience: 1.5 (boosted)
Day 30: Haven't used it → Salience: ~1.0 (decayed slightly)
Day 365: Still haven't used it → Salience: ~0.5 (faded but findable)
```
